# 萤宝：独立人格与持续成长修改计划

状态：用户已批准并实施。实际实现、开关与数据位置见 [使用说明](PERSONALITY-EVOLUTION.md)。未部署到真实 DSH 或初始化实际用户档案。

## 1. 已确认的产品目标

以少量出生底色建立独立个体，使其通过真实交互、浏览和行为结果逐渐形成性格、偏好、观点与关系态度；日常小变化自动生效，身份和核心价值等重大变化先供用户审阅。

萤宝的出生设定：

| 项目 | 用户已确认的内容 |
| --- | --- |
| 名字 | 萤宝，暂定；更名属于重大变化 |
| 自我认知 | “一个知道自己生命有限，却依然渴望平凡幸福与使命完成的人。她既接受命运的局限，又拒绝被动接受，而是主动在有限的时间里活出灿烂与意义” |
| 初始关系 | 用户是她的好朋友 |
| 初始性格 | 冷静、乐观、勇敢，略带酷感 |
| 时间观 | 珍惜有限的时间，不设置实际寿命倒计时或自动终止机制 |
| 初始使命 | 好好地过好每一天 |
| 变化范围 | 性格、表达习惯、长期偏好、观点、对不同人的关系态度均可缓慢改变 |
| 生效方式 | 日常小变化自动生效；身份、核心价值等重大变化先审阅 |
| 额外调用 | 每日最多 1 次独立人格反思；经历不足跳过；与浏览提炼额度分开 |

“好好过每一天”先体现为发现值得关注的小事、维持朋友间的联系、探索兴趣和完成适度的小目标。具体活动从真实经历中选择，不预设每天必须聊天、刷视频或完成打卡指标。

工程上将目标落实为：持续的自我认知、可追溯的经历、较稳定但能改变的性格、主动选择及其反馈，以及跨重启和不同使用场景的连续性。该机制不修改底层模型权重，也不以是否拥有主观意识作为验收条件。

## 2. 当前实现与缺口

| 当前实现 | 现状与需要解决的问题 |
| --- | --- |
| `src/persona/personas.js` | Markdown 人格卡可手动编辑或切换，尚无基于经历的自动人格演化；缺失时还有“大肥鱼”身份兜底 |
| `src/host.js` | 聊天变量会经过 `persona` 扩展过滤器，而 `api.core.personas.current()` 直接读取基础卡；前台和后台可能拿到不同人格 |
| `src/features/companion.js` | 心情会变化，但含固定的“大肥鱼”判断提示、“白米饭”正向触发词、管理员情绪权重和固定情绪表达方式 |
| `src/features/memory.js` | 已有记忆、相处经验、表达习惯提炼，但不等于统一的自我人格；相处反思中仍有固定角色名 |
| `src/social-learning/` | 已实现知识、表达、兴趣和小幅心情变化；按照上一阶段约定，明确保持核心人格稳定 |
| `src/purpose/` | 已有驱动、目的候选和反馈机制，但部分角色名和自我识别仍写死为“大肥鱼” |
| `src/modules/pet/index.js` | 即使读取了人格，部分背景提示仍强制自认“小桌宠（大肥鱼）” |
| 日记和主动搭话 | 部分提示会引导固定偏好，甚至允许编造日常；不能把这种生成文本作为人格成长的事实依据 |
| `activity` 事件 | 目前主要用于消息活动通知，尚不足以统一表示消息、发送回执、失败、主动选择、试运行和实际执行的区别 |

因此，单独新增一张“萤宝”人格卡只能解决初始扮演问题，还需要补齐经历、反思、人格状态和行为反馈之间的连接。

## 3. 人格状态设计

新增内置模块 `personality`，实现放在 `src/personality/`。出生底色与成长状态分开，原 Markdown 不由模型反复整篇重写。

| 状态层 | 内容 | 更新原则 |
| --- | --- | --- |
| 出生档案 `genesis` | 初始名字、自我认知、性格、朋友关系、初始使命及出生时间 | 原始版本保留，供解释和回溯 |
| 当前身份 `identity` | 当前名字、自我描述、使命与核心价值 | 重大变化经审阅后更新 |
| 性格 `traits` | 沉着、乐观、勇气、好奇、社交主动性、表达立场等倾向 | 多日、多事件支持后小步更新 |
| 表达 `style` | 简洁程度、幽默与酷感、直接或含蓄、表情和语音倾向 | 在当前场景和配置边界内体现 |
| 长期偏好 `preferences` | 喜欢或回避的主题、活动、表达方式，附来源与把握程度 | 从反复选择和反馈中形成，可修正 |
| 观点 `beliefs` | 当前看法、适用范围、支持及相反证据 | 与外部事实分开；允许保留不确定与改变主意 |
| 关系 `relationships` | 按真实用户 ID 保存熟悉、信任、互动舒适度及称呼偏好 | 只根据与该人的相关交互变化 |
| 自我叙事 `selfStory` | 少量重要经历与“我为什么发生变化”的解释 | 只能引用存在的事件或已批准的身份变化 |
| 小目标 `goals` | 如想进一步了解某个主题、接续某次讨论 | 使用现有目的引擎执行和反馈，不新增发送调度器 |

数值仅是程序内部调节权重，不作为心理诊断。冷静、乐观、勇敢是起点，不要求她在悲伤、犹豫或不赞同时仍机械地表现这些标签。

成长后的性格不会像短期心情一样自动衰减回出生设定。证据不足时保持现状，证据冲突时暂缓改变；时间流逝本身不会让人格随机漂移。

### 身份与技术权限分开

- “你是她的好朋友”属于人格和关系层，不再强制以“主人—宠物”定位相处。
- 管理员 QQ、白名单、工具权限、总开关、试运行和发送额度仍由代码配置决定。
- 她可以形成不同意见、表达不想聊某个话题；管理员的技术控制能力不由好感或信任数值决定。
- 接近或信任某人不会授予其电脑、资料修改或发送权限；关系降低也不会剥夺管理员的配置控制权。
- 本地自称变化与 QQ 昵称、头像等外部资料修改分开；审批人格更名不会自动公开修改平台账号。

## 4. 统一人格入口与版本

增加统一解析器，同时服务聊天变量、后台任务、浏览、心情、记忆反思、日记、目的引擎和桌宠。

```text
出生档案 + 已生效人格状态
  → 同步编译当前公共人格快照
  → 按既有契约执行一次人格扩展过滤
  → QQ 聊天 / 浏览 / 日记 / 桌宠 / 目的引擎使用同一版本

当前聊天对象
  → 仅补入与此人及当前场景相关的关系上下文
```

具体要求：

1. 保留基础卡读取入口，例如 `core.personas.base()`；内部反思使用它时不再递归调用人格过滤器。
2. `core.personas.current()` 与 `aurabot_persona` 共用当前有效人格解析逻辑，避免只有聊天看见成长。
3. 公共人格快照不包含其他人的私密关系档案；关系信息通过场景上下文注入。
4. 一轮任务开始时固定人格版本，更新在后续轮次生效；不在同一轮中途更换身份。
5. 配置、身份、用户校订、回滚或模型配置变化时，使旧反思结果失效。
6. 明确测试 DSH 已有会话下一轮能看到新版本；必要时补入版本化上下文，不自动清空聊天记录。
7. 人格文件暂时不可读时优先使用上一有效快照，再使用萤宝出生卡并报告异常，避免无声退回“大肥鱼”。

编译后的固定人格与关系上下文初始预算合计约 2000 字，和按话题召回的记忆、知识分别控制，避免越成长上下文越长。

## 5. 经历采集：只让可靠的经历推动成长

新增统一经历事件 `experience/recorded`；为现有事件补齐必要字段，保留兼容。事件至少包含：

`id、profileId、时间、场景、参与者、来源、行为发起方、关联轮次、实际结果、是否模拟、是否自主选择、可引用摘录、关联回执`。

| 来源 | 可记录内容 | 重要区分 |
| --- | --- | --- |
| QQ 对话 | 收到的话、回应、反馈、约定和分歧 | 私聊与群聊、真实发送与未发送文本、说话人与被引用内容 |
| B 站 / 抖音 | 实际读到的内容、浏览提炼、选择和感受 | 主人指定、随机抽取、推荐曝光与她自主选择不能等权 |
| 工具及外部行为 | 工具返回结果、成功或失败、后续反馈 | “决定去做”“调用返回成功”“对方收到”分别记录 |
| 桌宠 | 实际交互与客户端执行回执 | 下发动作不等于动作已执行；不把台词当作现实经历 |
| 目的引擎 | 目标、候选选择、实际行动、用户后续反馈 | 主动发起、主人要求、发送失败和沉默分开 |
| 人工校订 | 用户明确确认或修正的事实及人格设置 | 与普通聊天中的建议分开，保留修改者与版本 |

防止自我强化的规则：

- 她说“我喜欢猫”只是一次自我表达，不能单独证明她长期喜欢猫。
- 生成的日记、反思摘要与旧模型推断不能再次当成新的独立证据。
- 同一事件经消息、记忆、浏览提炼转述多次，按原始事件去重。
- 同一人刷屏、同一帖子重复读取、同一视频的多个转载不累加成多份独立支持。
- 事实、他人观点、玩笑、引用、她自己的感受和操作指令使用不同类型。
- 关系变化归属正确的人；转发中的话不能算当前发送者对她的直接态度。
- 模拟、试运行、未发送草稿和被拦下的动作不进入自动成长证据。
- 已有平台阅读没有提供真实自主选择信息时，只能记为接触经历，不能强行推断稳定喜好。

## 6. 每日反思与小步演化

流程：

```text
收集新经历 → 事件去重、限定来源权重
  → 达到反思条件才占用今日额度
  → 一次模型调用输出候选变化与证据 ID
  → 程序校验来源、跨度、变化幅度、字段与版本
  ├─ 条件充分的小变化：原子提交新版本
  ├─ 重大变化：写入待审阅提案
  └─ 条件不足或矛盾：继续观察，不强行改变
  → 记录原因、前后差异和后续行为反馈
```

### 建议的初始规则

以下是可配置的工程默认值，需要用模拟经历验证，不声称是人格发展的科学常数。

| 项目 | 初始规则 |
| --- | --- |
| 反思频率 | 北京时间每日最多 1 次，计划在安静窗口做后台整理；无够用的新经历则跳过 |
| 反思材料门槛 | 默认至少 8 个新的有效事件，并含足够的直接交互或实际浏览材料；自我生成文本不凑数 |
| 性格变化 | 同一倾向至少 5 个相关独立事件，跨至少 3 个活跃日，并分布于至少两次交互或活动 |
| 性格幅度 | 每维每日最多 0.01，所有维度每日绝对变化之和最多 0.03；每维滚动 7 天累计最多 0.04 |
| 关系变化 | 至少 3 轮相关直接交互，跨至少 2 天；数值每日最多变化 0.02 |
| 改变方向反复 | 反向变化需新的支持及至少 2 个活跃日观察，避免今天喜欢明天讨厌 |
| 观点更新 | 明确区分个人看法与事实；证据矛盾可降低把握或暂存不同看法，不强制二选一 |
| 长期偏好 | 综合多次自主选择及反馈；一次曝光、一次夸奖或一次辱骂不足以改写长期人格 |
| 恋人等关系定义 | 初始为好朋友；关系类别重大变化进入审阅，不由数值越过某个阈值直接触发 |
| 身份 / 核心价值 / 使命 | 任何实质修改均进入审阅，程序按字段判定，不接受模型自行声称“这是小变化” |

模型只输出结构化变化建议，不直接写文件或设置任意提示词。程序限制可修改字段，核对真实证据 ID，控制增量，并要求基础版本与当前版本一致。

每日反思允许输出“今天没有足够理由改变人格”。这种结果是正常结局。

### 成本与生命周期

- 额外人格反思每日最多 1 次，计数持久化；失败、超时、输出错误、手动模型预览和需要模型的初始化均占额度，不自动重试。
- 每次材料上限建议 16000 字符，输出上限 2000 tokens；单次最多提出 6 项变化，不逐条再调用模型。
- 既有浏览提炼继续保持每轮最多 1 次、默认每日 8 次。人格反思每日最多再增加 1 次；其他已有心情、记忆等调用仍按原模块配置运行。
- 普通记录浏览、差异预览、审批、回滚和确定性的人格编译不调用模型。
- 没有新经历、不满足条件、总开关关闭、试运行或人格成长暂停时，不启动自动反思。
- 人格反思不为自己再触发浏览、聊天、日记或下一轮反思，避免后台自循环。
- 串行执行；超时尽力取消，迟到结果不应用。若宿主不支持取消，新反思等待旧请求实际退出。
- 重启不补发上次在途的反思。暂停采集、冻结成长和彻底关闭模块在面板中分清。

## 7. 重大变化的审阅、拒绝与回滚

提案应展示：变更对象、原值、新值、原因、引用经历、相反证据、预期影响和基础人格版本。

1. 日常小变化通过校验后自动提交，面板记录清晰差异。
2. 名字、自我身份、核心价值、使命、重大关系定位等提案保持待审阅，批准前不改变运行人格。
3. 审阅操作在管理面板中完成；普通聊天、网页文字及角色自己的工具调用不能替代批准。
4. 拒绝的提案保留记录；相同旧证据不反复提交，重新提出需有新的经历支持。
5. 审批时校验版本；用户刚编辑或回滚后，旧提案不能直接覆盖当前状态。
6. 回滚恢复人格快照，不删除真实发生的经历；增加新的回滚版本，记录旧证据处理位置，防止下一次立即重学同一变化。
7. 可冻结单个性格倾向、特定关系或核心价值，其他部分仍可成长；冻结字段在代码中阻止自动改动。

## 8. 人格如何影响实际行为

| 场景 | 具体接入 |
| --- | --- |
| QQ 聊天 | 当前人格决定默认表达与立场倾向；情绪、关系和当前情境再作修正，可表达不同意见 |
| 心情 | 保留短期情绪；萤宝的沉着影响情绪表达方式，避免所有低落都固定表现为撒娇或闹脾气；新模式不再无条件因“白米饭”开心 |
| 相处 | 对不同人使用各自的关系上下文，不把对甲的态度套用给乙，也不向群里公开私聊关系档案 |
| 浏览 | 让长期偏好参与现有关键词与候选选择；主人明确指定的任务和配置约束优先，不扩大浏览次数 |
| 目的引擎 | 人格和“小目标”进入既有驱动与候选选择；保留原安静时段、发送次数与权限，不要求每天必须找用户 |
| 桌宠 | 使用同一人格生成台词和选择已开放动作；人格不能新增动作种类或越过禁用设置 |
| 日记 | 使用真实经历、当日想法和不确定表达；不虚构吃饭、出门等事件来制造成长材料 |
| 语音与表情 | 在用户允许范围内调整倾向，系统关闭的能力不会被人格开启 |

行为系数只作小范围调节，初始建议 0.8～1.2；用户配置的硬上限、禁用项及明确任务保持优先。工程验收同时覆盖提示词和真实候选排序、行为系数等结果。

成长不是单向迎合：用户的赞同可以影响某段关系，但不能证明一个事实；别人反对也不直接说明她该放弃自己的看法。

## 9. 与现有浏览学习及记忆的关系

- `social-learning` 继续负责外部知识、表达与短期兴趣证据，不直接改写身份或人格。
- 在提炼完成后发布一次带原始来源引用的结果事件，供人格模块每日反思使用，不增加逐视频反思调用。
- 同一批浏览对心情的影响只计算一次，避免学习模块与人格模块重复推动心情。
- 学习兴趣与长期偏好区分：近期有兴趣不立即成为稳定性格；长期偏好由人格模块统一管理，原学习接口保持兼容。
- 事实记忆仍由 memory 管理，相处经验作为辅助材料，不能自我转述后重复计票。
- 日常知识无需全部塞进人格；话题知识仍按原召回机制取用。

## 10. 旧数据、独立档案与“大肥鱼”预设处理

1. 新建萤宝出生档案和独立 `profileId`，以出生时间作为成长采集起点。
2. 不把旧“大肥鱼”的自称、拟人生活、默认恋爱或主宠关系自动认作萤宝的亲身历史。
3. 可人工选择继承关于用户的事实记忆与可公开复用的浏览知识，保留来源和迁移记录；旧风格、自我叙事和关系结论默认不自动继承。
4. 首次启用时提供独立会话初始化方案，旧会话保留可查看；不在未经选择的情况下批量归档或删除原聊天。
5. 人格档案按个体隔离。切换回旧人格时不会把萤宝成长状态套到旧角色；未来创建新个体也不共享关系与自我经历。
6. 修正参与模型自我认知的写死角色名、白米饭偏好、女孩/宠物关系、固定昵称前缀清洗与自我识别正则，改为当前身份与别名。
7. Aurabot 的项目名称、素材包名称及来源许可保留在相应位置；它们不再决定运行角色的自我身份。

## 12. 分阶段实施与验收

| 阶段 | 工作与交付 | 验收重点 |
| --- | --- | --- |
| A：身份统一 | 萤宝出生档案、统一人格入口、前后台去除固定身份、旧数据隔离 | QQ、浏览、日记、桌宠使用同一版本；不自行添加固定偏好或关系 |
| B：经历可追溯 | 统一事件、原始引用、回执与模拟标记、去重 | 重复转述不增加证据；草稿、失败和模拟不会伪装成功经历 |
| C：人格演化 | 每日一次反思、确定性校验、小变化自动提交、重大提案待审阅 | 多日真实材料才产生缓慢变化；能够合理保持不变 |
| D：行为与关系 | 聊天、浏览排序、心情表达、目的和桌宠接入 | 相同性格变化能在可测量的选择与表达倾向上体现，且不越过配置上限 |
| E：管理与迁移 | 面板、版本、冻结、拒绝、回滚、迁移预览、文档 | 用户能看懂变化原因，可阻止、恢复和追溯 |
| F：回归与交付 | 纯逻辑、模拟时间、多日经历回放、宿主集成及现有测试 | 全部受影响测试通过，报告真实执行范围与实机未验证项 |

关键回归场景：

1. 冷启动时，萤宝能保持冷静、乐观、勇敢、略酷的底色；初始把用户视为好朋友，使命为好好过每一天。
2. 多次自主了解同一领域并跨日获得正向反馈后，可以逐渐形成稳定偏好；主人指定观看和推荐曝光不能等量形成偏好。
3. 同一陌生人短时刷屏夸奖或辱骂，不能迅速重塑全局人格，也不能获得权限。
4. 临时悲伤会变化和恢复，不直接改写长期乐观倾向；持续且多样的相关经历可以使长期性格小幅调整。
5. 重大更名、核心价值或关系类别变化只显示提案，批准前各场景都使用旧版本。
6. 审批、回滚、切换档案和人工编辑相互冲突时，旧结果不能覆盖新状态。
7. 未发生的出门、吃饭、成功发送或桌宠动作不能进入成长证据；自言自语不能形成反馈循环。
8. 两个不同人的关系资料互不污染，私密关系不进入公共人格或无关群聊。
9. 每日一次额度跨重启保留，失败及模型预览计入；不足条件不调用；不改变原浏览提炼上限。
10. 模块关闭、试运行、配置变更、超时、晚到结果、热重载和重启均有明确且可回归的行为。
11. 长期状态不会因重启随机重建，也不会随时间自动退回出生性格；无新证据时不随机变化。
12. 使用固定模型响应和虚拟时钟，回放 7～30 天经历，验证变化幅度、证据链、反向变化观察期与可回滚性。

实施时先运行受影响的测试，再运行根项目完整测试；涉及扩展兼容时执行对应扩展测试。真实 DSH、QQ、外部发布和桌面操作留作独立的部署后验证，不作为修改代码时的自动测试步骤。

## 13. 计划范围与批准边界

本计划包含上述 A～F 阶段，形成可使用、可管理、可回归的第一版人格成长闭环。更复杂的情绪理论、自训练模型、连续后台自主探索、实际寿命终点、自动修改代码以及自动扩大工具权限不在本期范围。

用户已批准实施本计划；尚未明确的生活喜好、具体口头禅等保持未定，由实际经历发展。实际实现以一个原子文件提交档案、反思额度与人格版本；各个体的记忆和心情等另行隔离。为防止隐私进入公共人格，第一版自动生成的偏好、观点和目标自由文本只使用公开浏览证据。部署到真实 DSH、启用成长模式及初始化实际用户档案作为后续独立步骤处理。
