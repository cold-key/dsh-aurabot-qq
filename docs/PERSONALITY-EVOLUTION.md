# 萤宝：人格成长使用说明

本功能实现独立出生档案、真实经历、每日反思、小步性格变化、重大提案审阅和版本回滚。默认关闭，原有人格卡继续可用。修改计划及初始设定见 [设计计划](PERSONALITY-EVOLUTION-PLAN.md)。

## 创建与启用

在 Aurabot 面板进入「人设 → 人格成长」：

1. 查看出生档案预览。预填名字“萤宝”，冷静、乐观、勇敢、略带酷感；管理员最初是她的好朋友；使命为“好好地过好每一天”。珍惜有限时间是价值观，没有实际寿命倒计时。
2. 可修改名字、自我认知、使命、初始关系和性格系数，再点击“创建独立出生档案”。这一步不调用模型，也不会启用档案。
3. 在档案列表点击“选择并启用”。创建的专属出生卡与成长档案关联，后续各场景读取当前人格。
4. 插件总开关开启且退出试运行后，才自动采集经历和反思。实际平台是否浏览、发送仍由原配置决定。

不会自动登录、部署或修改 QQ 昵称、头像。面板显示的当前人格名称可随批准的变化更新，平台账号资料保持原来的操作流程。

新个体不自动继承旧角色的自我经历、情绪和关系结论。成长页可查看并勾选继承旧库中的部分人物事实，原记录保留；公开浏览知识仍可通过已有浏览学习召回。需要新聊天上下文时，可填写 `private:QQ号` 或 `group:群号`，明确归档该会话，下一条消息独立开始；旧会话保留，不自动批量重置。

如果已用用户模块替换 memory、mood、purpose、pet 等内置模块，应对照新增接口接入，或在扩展页选择内置实现；插件不会覆盖你的自定义版本。

## 成长如何发生

人格分为出生记录、当前身份、性格倾向、表达风格、长期偏好、观点、关系、小目标和少量自我叙事。长期人格不会随时间自动回到出生值，短期心情仍按原机制恢复。

经历采集包括实际 QQ 输入、已读 B 站/抖音材料、模块工具成功结果、已知桌宠动作执行回执和真实交互。角色自己的聊天、生成的日记与反思不算独立证据；草稿、模拟、失败和出生前材料不会推动人格成长。重复来源去重，公开浏览的相同文本跨日也去重；语义不同的转载仍可能无法完全识别。

浏览曝光只代表接触，不自动代表喜欢。B 站自主评论、抖音自主点赞等已确认选择可补充原视频的自主选择标记，不增加一份内容证据。用户指定或手动触发的浏览不等量计作自主偏好。

默认在北京时间 03:00 后的定时检查中，满足以下条件才开始一次独立反思：

- 至少 8 个有效新事件，包含直接交流或实际浏览材料。
- 总开关开启、试运行关闭、当前档案已生效且成长未冻结。
- 今日人格反思额度尚未使用。

反思允许得出“无需改变”。性格或风格自动变化至少需要 5 个相关独立事件、跨 3 个活跃日；每维每日最多 0.01，性格及风格总日变化最多 0.03，每维滚动 7 天最多 0.04。反向变化还需两个活跃日的新支持。关系数值至少跨两天的相关直接交互，每日最多变化 0.02，不使用其他人的证据。

长期偏好需要跨日至少 3 份相关自主浏览证据。为避免私密对话内容进入公共人格，第一版自动生成的自由文本偏好、观点和小目标仅使用公开浏览证据；私聊可影响数值性格及对应关系。观点始终标为当前看法，不代表事实核验。

这些阈值是可解释的工程限速规则，不是心理诊断。当前面板展示的数值也是程序倾向系数。

## 人格与行为联动

QQ 聊天、心情判断、浏览、记忆反思、目的引擎、日记与桌宠共用当前有效人格。前台与后台都经过同一套扩展人格过滤；关系背景只进入对应私聊。

- 当前名字加入群聊唤醒词。新模式不把原样保留的整组默认“大肥鱼”兴趣当成萤宝兴趣；用户显式改过的兴趣列表保留优先级，额外别名可在聊天页配置。
- 长期偏好参与已有浏览候选排序和至多一个学习搜索词，不增加浏览次数。
- 社交主动性、酷感等对聊天、语音、表情和节奏作 0.8～1.2 范围内的系数调节，硬上限与关闭项仍优先。
- 目的引擎可使用人格驱动和小目标；它仍需单独启用，保留原安静时间与发送限制。不同人格的目标状态隔离，目的调用次数使用共享账本。
- 独立人格有自己的心情和记忆库，出生后的聊天流水按档案标记；记忆整理中途切换个体，结果仍写回原库，不删除共享历史。
- 日记使用当前想法和实际经历，不再由提示强制喜欢白米饭或编造出门吃饭。

她可以表达不同意见和不想聊某个话题。感情、关系与技术权限分开，熟悉度和信任不会授权电脑操作、改资料、扩大白名单或增加发送额度。

## 审阅、校订、冻结与回滚

名字、自我认知、使命、核心价值、关系类别变化均为重大提案，显示原值、新值、理由及来源摘录。批准前不生效；可批准单项，或在查看后批准同一当前版本的全部提案。审批、校订、冻结和回滚均携带当前版本，旧提案不能覆盖新修改。

拒绝会记录提案指纹，没有新证据不会重复提交。成长记录显示已生效的小变化。回滚恢复旧状态并产生新版本，保留真实经历，同时将旧材料置为已处理，避免马上再次学回原变化。

控制方式：

| 控制项 | 行为 |
| --- | --- |
| 冻结成长 | 不进行反思或自动变化；采集是否继续由采集开关决定 |
| 关闭采集 | 不增加新经历；已有足够材料仍可反思，需完全暂停时同时冻结成长 |
| 冻结指定字段 | 可冻结全部身份、性格、风格、偏好、观点、目标、单个性格或某人关系 |
| 关闭成长模式 | 使用当前基础卡；成长档案保留，重新选择启用可恢复 |
| 切换普通人格卡 | 当前成长档案不再套用到普通角色；以后可重新选择档案 |
| 人工校订身份 | 在成长页修改当前名字、自我认知、使命，保留版本快照 |
| 直接编辑当前出生卡 | 关闭成长覆盖并采用人工卡内容，避免保存后被成长状态无声覆盖；档案保留 |

清除某人的关系时，同时清理近期关系证据、相关提案、变化摘录及快照中的关系字段。已经形成的全局性格不会假装从未受到影响，可另行人工校订或回滚。事实记忆库是独立功能，清除成长关系不会自动删除其中人物事实。

## 模型成本与故障处理

人格反思每日最多 1 次，`dailyMax: 0` 可关闭新增反思调用。失败、超时、格式错误和手动模型预览都消耗额度；发起前持久化扣除。浏览提炼维持自己的额度，原有心情、记忆、桌宠等模型调用按各模块原配置运行。

单次反思材料上限 16000 字符，输出上限 2000 tokens，最多 6 项候选。不逐条再调用模型，不因思考强度不兼容而重试。模型预览不应用变化，也不将材料标为已处理；无模型的状态查看、出生档案创建、校订和回滚不消耗反思额度。

实际反思在请求前记录已处理材料；失败或进程中断不会自动重放同一批次。180 秒超时后先结束管理等待，迟到结果不应用。若宿主不支持取消，物理通道仍等待旧请求结束，新反思不会并发发起。热重载也共享该通道。配置、模型、身份版本、人工修改或回滚会使旧结果失效。

未知或损坏的数据文件不自动覆盖。运行中读取失败时暂时保留上一有效人格，管理界面报告错误；修复文件后恢复读取。

## 配置与数据

配置位于 `ext.personality`：

```json
{
  "enabled": false,
  "paused": false,
  "collect": true,
  "dailyMax": 1,
  "minEvents": 8,
  "reflectHour": 3
}
```

默认用户目录中：

- `modules-data/personality/state.json`：版本化原子状态文件，包含档案、全局反思额度、事件、提案、快照和历史。集中提交额度与人格版本，避免多文件事务错配。
- `modules-data/personality/<profileId>/memories.json`、`mood.json`、`purpose-state.json`、`nudge.json`：对应个体的记忆、情绪和目的状态。
- `personas/life-<profileId>.md`：创建时保存的出生快照，不由反思整篇重写。
- `chatlog/*.jsonl`：沿用聊天流水，新增个体归属字段。

以上路径支持 `AURABOT_DATA_DIR` 重定向，不提交到 Git。近期事件最多 5000 条、90 天；原始来源去重索引和已处理索引各最多 10000 条；已生效变化最多 1000 项、提案 50 项、快照 200 个。重要经历摘要最多 200 条，出生档案保留。详细数据可能含私密对话摘录，请按原用户数据方式管理备份。

接口位于 `/aurabot/api/personality/*`：GET `status`、`legacy-memories`；POST JSON `create`、`activate`、`reflect`、`review`、`edit`、`freeze`、`rollback`、`forget-relationship`、`import-memories`、`reset-chat`。接口参数及事件见 [模块契约](../src/modules/API.md#独立人格与真实经历) 和 [类型声明](../src/modules/aurabot.d.ts)。
