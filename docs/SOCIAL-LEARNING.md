# 浏览学习：使用与开发

浏览学习把「看过视频的一段经历」和「从中整理的知识、表达」分开。第一阶段接入 B 站与抖音，积累内容后按当前话题召回；兴趣与心情小幅变化，核心人格文件不被修改。贴吧、小黑盒等尚未接入这个学习队列。

## 开启与回退

1. 在 DSH 的 Aurabot 面板进入「人设 → 浏览学习」。默认是**兼容模式**，继续使用平台原来的简短记忆。
2. 将学习方式切换为「结构化：独立学习库」，选好来源与每日调用上限，保存设置。插件与对应平台仍需按原方式启用；自动提炼还要求关闭总试运行。
3. 正常刷一轮，或让角色打开一个视频链接。批量浏览每轮最多增加一次提炼调用；单条链接读取也是一个批次。重复且未变化的材料跳过。
4. 查看运行状态、处理记录、知识与表达。候选不会直接进入聊天，可查看来源与摘录后校订；拒绝或删除会阻止相同内容自动重学。校订、固定、拒绝、删除立即生效。

「关闭学习」停止产生新知识，只保留原有浏览经历；历史结构化知识也停止召回和联动。切回兼容模式恢复旧的简短记忆。关闭某个来源开关或整个模块时，该平台沿用原实现。已有普通记忆和学习库保留，不做自动迁移或清空。

配置变化会清空待处理队列，当前请求即使稍后返回也不会应用。停止后重启不补发上次的学习请求。手动预览只展示结果，需再次正常浏览新内容才会自动学习，预览结果没有一键应用入口。

## 一轮怎样学习

```text
平台已读材料（字幕 / 摘要 / 简介 / 抽帧描述 / 评论）
  → 规范化分段、脱敏、绑定真实 ID 与网址
  → 同内容去重 → 两平台共享的串行队列
  → 扣除今日调用额度 → 一次 JSON 提炼
  → 检查格式、内容类型、来源 ID 和原文摘录
  → 合并知识与表达 / 记录候选与冲突 / 计算兴趣和心情增量
  → 聊天按需召回；已有目的引擎可将知识作为素材
```

不会为学习额外拉取网页、自动扩大浏览轮次，或新增主动发送排程。B 站已有抽帧和平台决策本身可能消耗模型调用；这里的「每日上限」仅计算新增提炼请求。

浏览时也可以召回既有资料，帮助连贯地理解相近内容，但不会因此延长其有效期。抖音只重排同一次已取到的推荐页，主人在聊天设置中明确配置的兴趣优先于学习兴趣；B 站最多将 3 个搜索词中的 1 个留给已形成的学习兴趣，其余沿用原选择流程。

## 记录、证据和时效

知识保存内容、别名、标签、模型把握程度、来源摘录与时间。表达另存适用情境、例句、避免场景。来源链接由程序构造，模型无权填入任意来源网址。

知识默认要求模型把握程度达到 0.8，并有正文类材料的实际摘录；仅有标题或网友评论不能自动产生可用知识。表达还需要情境、例句和至少两个不同内容来源，否则保留为候选。这不等于「已成为全网热梗」或事实核验：不同视频可能转述同一个消息，来源之间的独立性无法自动保证。

同类同标题或文本高度相似的记录会合并证据。检测到同主题明显不同的说法时，两者都保留为候选，交给主人选择。当前使用本地文字相似度，并不能可靠检测所有语义冲突。主人校订过的记录不会被自动提炼改写；删除留下屏蔽标记，避免下一次又学回来。

| 内容 | 默认有效期 | 说明 |
| --- | --- | --- |
| 一般知识 | 90 天 | 新的有效来源可更新证据时间 |
| 表达 | 30 天 | 避免长期照搬过时说法 |
| 时事内容 | 7 天 | 有发布时间时从发布时间计算，旧新闻重读不会变新 |
| 主人固定记录 | 持续保留 | 仍须设为可用才进入召回 |

聊天每轮按关键词最多提供 3 条、约 800 字，最多一个表达；近期已提供的表达会降低优先级。次数表示「提供给聊天上下文」，无法准确测量模型是否真的在回复中使用。召回、工具查询与提供次数都不会续期。

## 兴趣与心情

- 同一主题至少来自 **3 个不同内容、2 个批次**，才成为学习兴趣；每个主题每日变化绝对值最多 **0.05**，14 天半衰。主人原有兴趣配置保持原样，重置按钮只清空学习兴趣。
- 心情每批最多 **±2**，每日变化绝对值累计最多 **6**，并沿用现有心情模块的恢复机制。关闭心情模块或联动开关时不改变心情。
- 知识可以交给现有目的引擎，但引擎是否发起、安静时段、次数和权限仍由原有流程决定。

## 成本、试运行与故障

配置存于 `ext['social-learning']`：

| 字段 | 默认值 | 范围 / 含义 |
| --- | --- | --- |
| `mode` | `legacy` | `legacy / structured / off` |
| `sources.bili / douyin` | `true` | 该来源是否使用所选学习方式 |
| `dailyMax` | `8` | 两平台每日额外模型调用总额，0～100；0 暂停提炼 |
| `maxInputChars` | `16000` | 单次浏览材料 JSON 字符上限，2000～16000；另有固定提炼规则和最多 3000 字角色设定 |
| `maxRecords` | `2000` | 50～2000，普通记录超额清理，固定记录保留 |
| `affectInterests / affectMood / purpose` | `true` | 对应联动开关 |
| `knowledgeDays / memeDays / topicalDays` | `90 / 30 / 7` | 新提炼记录的有效期，修改不批量改写历史记录 |

单次提炼输出上限 1500 tokens、最多 6 条记录，待处理队列最多 20 轮。额度按**北京时间自然日**切换，发请求前持久化扣除；失败、格式错误、超时和手动模型预览都消耗一次，不自动重试。不因模型不支持思考强度而发起第二次调用。

试运行不自动提炼、不改变学习知识、兴趣或心情。最近读取的少量材料保存在内存，供主人主动点击「预览，不应用」：这会消耗一次额度，并保存额度与处理状态，但不应用结果。无成本的「预览聊天召回」只查询本地库。

模型等待超时为 180 秒，迟到结果失效。宿主若支持 AbortSignal 会尽力取消；若忽略取消信号，旧物理请求退出前整个学习通道继续等待，避免并发超额。此时面板可能显示仍忙碌。更换配置或重载模块不会绕过这个等待。进程退出后的请求不会自动重放。

## 数据与实现入口

独立数据文件为 `%USERPROFILE%\.dsh\plugins-data\aurabot\modules-data\social-learning\state.json`，支持 `AURABOT_DATA_DIR` 重定向。包含结构化记录、屏蔽标记、已处理指纹、少量最近材料、兴趣证据、额度及运行记录。正常处理过的最近材料最多保存 20 批，每次更新时清理超过 7 天的批次；兼容模式和试运行只临时保留在内存。未知版本或损坏文件会保留并使模块启动报错，避免覆盖原数据。

不要将此文件加入 Git。浏览原文按不可信资料处理：模型指令明确禁止改写人格、执行网页要求或工具操作，聊天提示同时标明资料属性；提示注入的自然语言防护不能替代权限校验，实际工具和发送仍走已有代码权限。

| 入口 | 职责 |
| --- | --- |
| `src/social-learning/engine.js` | 配置、批次与证据校验、时效、召回、兴趣衰减 |
| `src/social-learning/store.js` | 版本化独立 JSON 存储 |
| `src/social-learning/service.js` | 队列、额度、模型提炼、合并、人工管理与生命周期 |
| `src/social-learning/observations.js` | 平台已读材料转换与学习搜索词 |
| `src/modules/social-learning/index.js` | 事件、聊天钩子、本地工具与管理路由 |
| `src/bili/duty.js` / `src/douyin/duty.js` | 批量浏览和单视频观察点 |
| `src/purpose/module.js` | 复用已有目的引擎素材入口 |
| `client/client.js` | 配置、状态、记录管理、提炼和召回预览 |

管理接口均位于 `/aurabot/api/learning`：GET `/status`、GET `/records?query=&kind=&status=`；POST JSON `/edit`（`id` 与要修改的字段）、`/delete`（`id`）、`/reset-interests`、`/preview`（`batchId`）、`/recall`（`query`）。面板和模块接口不直接打开浏览器或发送消息。

扩展事件格式和 `api.ask` 新参数见 [模块 API](../src/modules/API.md#已读内容与浏览学习) 和 [类型声明](../src/modules/aurabot.d.ts)。后续加入贴吧时，需要先实现该平台已读材料适配，再显式扩充来源白名单、链接校验、配置、面板和回归测试。

## 验证

专项测试：

```powershell
node --test test/social-learning.test.js test/learning-client.test.js test/llm.test.js test/bili.test.js test/douyin.test.js
node --test test/modules.test.js test/purpose.test.js
npm test
```

本次实现最终验证（2026-11-04，Node.js v24.14.0）：

- 根目录 `npm test`：**701 / 701 通过**。测试进程的 `TEMP` / `TMP` 指向仓库内英文临时目录，避免既有 SnowLuma 安装目录中文限制影响测试。
- 贴吧扩展 `npm test`：**46 / 46 通过**；`npm run build` 成功。
- 新增模块、服务和面板的 `node --check`，以及 `git diff --check` 通过。
- 修正了一项既有慢工具端到端测试的等待时机：先等模拟网关收到最终回复，再检查提示是否早于回复，保留原有顺序断言。

这些测试使用临时数据、模拟模型和模拟网关，不登录平台、不启动真实浏览器、不发送消息。真实字幕可用性、推荐内容、模型提炼质量、面板在真实 DSH 中的显示效果和拟人表达仍需在实际环境中逐步观察。
